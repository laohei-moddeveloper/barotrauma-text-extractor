## 1. 根因与改动

rc2 的零译文根因是打包 EXE 缺少解释器要求的 `codex-rejected-cas.pem`，SSLContext 创建即失败，尚未发出 HTTP 就被误报超时。rc5 保留 rc3/rc4 的 TLS 资源检测、打包和证书验证，不使用跳过验证的方式联网。

本轮三项问题存在不同原因：首次每个名称都单独请求；重复模板只按完整原文缓存；慢请求阻挡后续批次；免费翻译缺少游戏词义；反复构建全项目、全量响应和集中遍历/应用控件增加处理开销。对应改动如下。

- **速度**：两个请求槽位滚动调度；最多 16 条后台排队，可见文字优先。短结构化名称每次最多 4 条合并为一个 HTTP，总查询不超过 480 UTF-8 字节，只取已有同优先级队列，不等待凑批。简介、对白、任务及受保护术语/格式的名称不混入。编号缺失、重复、错序使整包逐条回退；有效边界内的坏行独立回退。传输、TLS、额度错误不追加回退请求。游戏请求/回传仍每包最多 8 条，网络并发仍最多 2。
- **语境**：内置 **136 项**核对原版双语语言键的短术语，附参考快照哈希；增加游戏物品、设备、药物、生物、症状、职业用语。命中完整术语无需 HTTP；项目术语优先，并实际参与免费翻译。歧义项按原生语言键/名称/症状/职业语境限制。有限医学整句模板只处理明确已知条件与药物。武器 reload、封堵船体破口、船员与生物移动词义有受限规则；没有把游戏标题 Barotrauma 全局改成伤名。
- **缓存和恢复**：全文/片段按渠道、语言对、语境和有效术语隔离，重复并发片段合并；10000 项/8 MiB 上限。格式与术语保护标记损坏时保守回退，译文仍为未校对草稿。逐条错误、取消、限流、旧会话/任务/渠道隔离和后续有限重试保留；已有中文及已有译文跳过。
- **运行开销**：新增文字增量合入工程；无变化不反复构建原生 XML、写整份响应。新插件使用带序号和确认的最多 8 项增量；字面量不触发全局语言重载，原生键 XML 至多每 2 秒合并更新。采集遍历每步 32 节点，队列选择至多访问 64 节点，刷新每步 32 控件；持续响应不会反复重置刷新游标。桌面事件每轮最多 64 条并有时间预算；缓存、诊断写盘合并。250 ms 轮询配合元数据缓存，仍有文件 I/O 和 Hook 开销。

此外，Windows CI 暴露了原地更新状态文件的接收确认问题：相同大小的 ACK 可能拥有相同修改时间和文件身份，元数据缓存会误用旧 ACK，导致后续包停等。关键 ACK 现在直接读取文件。新增回归强制保持文件元数据不变；旧缓存行为可复现 `sequence 2 != 3`，修复后通过。其他无关键确认的读取仍可使用缓存。

## 2. 可选择的免费渠道

默认仍为 **MyMemory 免费接口**，免配置、无密钥。设置中可选择 **Google 网页兼容（实验）**，直连 `translate.googleapis.com`，没有中间转发站。后者不是有免费额度保障的正式 API，大陆可能无法直连，也可能被拒绝或限流。两者均有可用性、额度和翻译质量限制。

仅向选中的一个渠道发送原文和语言对，不自动转发其他供应商，不下载模型、不调用收费服务。渠道切换取消旧任务后续工作，晚到结果不写入新任务。已有草稿不会因切换渠道自动覆盖，需用户备份后清空相应草稿再重译。

## 3. 速度和语境对比

### 真实联网短名称（8 个自建物品名，单次配对，最多 2 并发）

| 渠道 | 逐条请求 | 合并请求 | 整组耗时：逐条 → 合并 |
| --- | ---: | ---: | --- |
| MyMemory | 8 | 2 | 3.866 s → 0.813 s |
| Google 实验 | 8 | 2 | 3.888 s → 1.442 s |

请求数减少 75%。这是特定云环境的小样本，运行顺序、服务端缓存和网络状态会影响耗时，不能承诺稳定倍数。所有原始译文及错误保留在 [名称实网记录](abysstext-rc5-network-names.json)，复现脚本 `tools/probe_name_batches.py` 需主动运行。

### 真实联网语境（6 句自建开发回归）

[原始记录](abysstext-rc5-network-terms.json) 使用相同 rc4 基线与当前代码：指定游戏术语命中从 rc4 MyMemory **1/6** 变为当前两个渠道各 **6/6**；网络请求由 6 降到 5，医学整句本地返回。例如 Crawler 不再成为“履带车”，Coilgun 不再成为“线圈枪”，reload weapon 不再成为“重新加载”。

这只衡量指定术语，**不是整句准确率、独立盲测或所有模组的正确率**。本次包含本地返回的单条中位耗时：rc4 MyMemory 1.3575 s、rc5 MyMemory 1.464 s、rc5 Google 0.205 s；MyMemory 最慢条目 5.103 s。因此没有声称长句首次单次 HTTP 整体变快。整句仍受免费服务延迟与语义能力限制。

### 无网络的等量合成对比

[Windows CI 原始记录](abysstext-rc5-windows-benchmark.json)，基线 `f3163db`，同一 2000 条自建工程；增量接收端先完整收到同一基线，再修正其中相同的 8 条：

| 指标 | rc4 | rc5 |
| --- | ---: | ---: |
| 100 条仅占位符值不同的重复模板：模拟 HTTP | 100 | 1 |
| 相同 8 条修正的响应大小 | 68202 B | 682 B |
| 空闲发布 50 次的墙钟耗时 | 2.001757 s | 0.000212 s |
| 无变化是否仍重写响应 | 是 | 否 |

响应减小 99%。墙钟耗时不是 CPU 占用或 FPS；没有把第一包 8 条与首次全量同步混比。Linux 10000 次热缓存查找的另一合成样本为 0.7192 s，额外 Python 分配峰值约 0.002 MiB，没有网络请求。

## 6. 剩余问题及本机步骤

未知模组新词仍可能错译：此次 MyMemory 把 `Plasma Vent` 译成“血浆通风口”，Google 把 `Abyssal Relay` 译成“深渊接力”，逐条模式也有同样歧义。没有靠全局替换掩盖这些问题；应根据模组实际含义导入项目术语，或人工校对。136 项词表来自已有原版双语快照，不代表最新游戏或所有模组词汇。对图片、自定义绘制、未加载内容、全部动态对白路径、同文异义、第三方 Hook、引擎 getter/语言重载/字体布局仍有覆盖与开销边界。

你本机当前安装版本没有在本轮读取。要启用完整改进，按 [rc5 安装与回退](../../docs/INSTALL-rc5.zh-CN.md)：

1. 保存工程，停止试译，退出旧工作台；备份自己的程序/插件，把插件备份移到 LocalMods 外。不修改其他模组或存档。
2. 下载并用 PowerShell `Get-FileHash 文件名.zip -Algorithm SHA256` 核对 Windows 与插件 ZIP。解压到新目录，确认启动 rc5；更新自己的插件，旧 Live 状态文件不搬入。安装器仍拒绝覆盖已有目录。
3. 使用新报告路径执行 `BarotraumaTextExtractor.exe --check-online 新报告.json`；Google 另用新路径加 `--online-channel google`。根据本机可达性选择渠道，默认 MyMemory 不要求任何 API 配置。
4. 由你自行启动游戏并重新加载自己的 Lua。验证新物品/生物名称和简介、症状、任务/对白、已汉化文字跳过、可见提示优先、颜色/占位符/换行、断网和换回合恢复、停止重开。旧草稿不会被自动重译。
5. 特别观察打开背包、首次遇到新内容和连续译文到达时的帧时间，比较关闭/开启插件的同一场景。没有实际数据前不宣称零卡顿。出现问题保留版本、复现和错误信息；需要回退时停止插件和工作台后恢复自己的备份。

云端没有控制桌面、替换游戏 DLL、修改第三方模组或存档，没有下载模型或调用收费服务。此次完成的是可下载、可核验的候选，仍由你决定本机更新和游戏验收。
