# 工坊人工汉化缓存

译潜可以把已有人工汉化与原模组英文核对后，保存为本机缓存。命中时直接本地返回，不发给免费翻译接口或 AI；未命中仍走你选定的渠道。离线复用模式也支持该缓存。现有中文继续跳过，已有工程译文不自动覆盖。

## 使用

1. 本机订阅所需原模组及[老虎脱粒机汉化整合包](https://steamcommunity.com/sharedfiles/filedetails/?id=2861028841)，让 Steam 下载完成。不需要为了导入而启用汉化包或执行它的 Lua。
2. 更新工作台后，点击侧栏“导入工坊人工汉化缓存…”，选择包含这些包的同一个目录：通常为 Barotrauma 用户数据下 `WorkshopMods/Installed`，也可能是 `steamapps/workshop/content/602960`。原模组与汉化包都必须可读。导入在工作台后台进行，不在游戏绘制线程扫描文件。
3. 完成后按原来的游戏内一键翻译操作。缓存自动持久使用，无需每次导入。更换语言、更新原模组/汉化包后可重新导入。重建替换旧缓存；选错目录、零可靠配对不会删除原缓存。
4. 新插件提供模组来源 ID，让无语言键的预载名称也能按模组查找。旧插件仍兼容，但来源不明的短词不会猜测复用。只更新 EXE 不代表完成插件更新；游戏测试由用户自行操作。

缓存位于 `%LOCALAPPDATA%/AbyssText/human-memory.sqlite3`（无该变量时为 `~/.config/AbyssText/`）。删除此文件可回到原有联网/术语机制；先退出工作台。

命令行也可使用：

```powershell
.\BarotraumaTextExtractor.exe --import-human-memory "D:\模组库\Installed" --cache-path "D:\AbyssText\human-memory.sqlite3" -o "D:\AbyssText\新导入报告.json"
```

省略 `--cache-path` 才写入工作台默认使用的缓存。报告路径需为模组库之外的新文件。程序只读模组文件，不安装、修改或执行第三方模组。

## 质量与覆盖边界

- 按明确原包路线、语言键、当前英文原文配对；保存提供者工坊 ID、包版本与文件 SHA256。先检查占位符、颜色标记、换行、空白及控制字符。不同原文不会借用同名键的旧译文。
- 多个提供者译法冲突时不随意选一个；改走既有渠道。用户显式术语优先于导入译文。名称合并请求同样先排除人工命中。
- 每个 XML 最多 16 MiB，缓存最多 20 万候选；SQLite 索引按需查找，不把全部人工译文塞进网络提示词。禁止 DTD/实体、符号链接文件和越界文件引用。
- 不是全覆盖。当前路线涵盖 NT 本体及 Infections、EA、AA、AOCS、EK、Hungry Europans、Abnormalities 等可验证双语内容，以及合集内部分独立汉化。缺失原扩展包、只有脚本字面量、非普通语言表的故事/对话、原文已变及冲突条目不导入。完整路线与待确认项见 `assets/human-translation-sources.json`。
- 人工来源不是语义无误的证明；例如作者译法、旧内容、同文异义仍需校对。游戏桥接最终仍有按原文字面量替换的边界，不能据此宣称所有同名文本都已按模组隔离。
- 不保证网络未命中条目的速度，不宣称零开销或提升游戏 FPS。可见文字优先、每次最多 8 条、有限并发及原有缓存保持。

## 来源与分发

译文仍属于老虎脱粒机汉化组及各原译者。程序不是这些人工汉化的原创作者。[作者合集](https://steamcommunity.com/sharedfiles/filedetails/?id=2850943086)及工坊各条目保留署名。本仓库只分发导入器、来源路线和测试夹具，不把第三方译文、脚本、原模组或下载内容提交到 Git。缓存由用户本地已订阅文件生成。
