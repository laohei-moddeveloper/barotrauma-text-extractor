# 大量文本与持续翻译卡顿修复候选

本轮针对游戏端的重复工作，不改变翻译渠道、人工缓存或术语逻辑。

- 新译文不再建立全部控件的更新快照。轮转检查每帧最多 16 个槽位；无关译文不读取控件 Text，不反复触发布局。
- 每帧最多采集 32 个文本控件、分析 64 个新观察；数字字符串归一化额外限制 64 次/8192 字符。超预算留待后续采集，已有精确译文仍直接查询。
- 控件登记与恢复记录共用 3000 上限。超过上限的控件不再创建未登记的恢复项，仍可由字体绘制接口替换文本。10 秒未再观察到的旧控件分批恢复并释放引用，随后新页面可复用空位。
- 长提示框缓存已构造的富文本。数字模板、提示框及已有中文使用有条目/字符上限的缓存；停止试译时清理，译文修正/移除仍会失效并更新。
- 原生语言资源重载间隔至少 5 秒，并合并连续更新，避免持续使全局语言缓存失效。最终更新不会一直饿死，但原生语言键可能需等待约 5 秒及后续轮询；可见文字的字面量替换仍继续。旧协议首次加载保留即时行为。
- “已请求试译”日志最多每 5 秒一次；请求本身仍最多每批 8 条、每 250 ms 尝试发送，保留序号/会话确认及可见优先。

## 更新与验收

退出旧工作台，备份并更新自己的配套工作台和插件。若游戏已运行，应由用户自行在安全时机重载自己的 Lua/重启游戏，避免仍运行旧 Lua。不要替换游戏 DLL、第三方模组或存档。原人工缓存无需重新导入。

新版插件 `Live/status.json` 的 `runtime_build` 为 `bounded-render-fix-20261023`，另有 tracked_controls、last_control_visits、numeric_cache_entries、tooltip_cache_entries、render_cache_chars、language_reloads，方便核对是否真的启用新版。不要把旧运行状态误当成新包已生效。

本机请比较同一大页面开始/持续试译、切换多个页面后再返回、长提示框与动态数值、修正/移除译文、停止恢复。记录实际帧时间及卡顿时这些计数。本轮隔离压力测试不等于真实游戏 FPS 验证。引擎单次 getter、布局、字体渲染、XML LoadFile、其他模组及桌面程序的工作仍有成本；本轮没有证明已解决所有卡顿。停止试译的恢复和全局语言资源的单次载入仍可能产生一次开销。
