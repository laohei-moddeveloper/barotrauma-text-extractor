# 离线复用与持续翻译减负

## 这次改善

- “离线复用”除了已有工程记忆和导入的人工汉化，也会读取当前渠道、语言对和术语策略匹配的联网译文缓存，以及能够完全确定的单条术语/医疗模板。未命中保留未翻译状态，不偷偷联网。人工译文的来源范围、冲突拒绝和用户术语优先规则保持原样。
- 短名称合并翻译中的人工/机器缓存命中直接返回结果，避免先查一次人工库、再调用单条翻译重复查一次。冷条目和服务端格式异常的独立回退逻辑仍保留。
- 桌面持续翻译把列表/编辑器的重绘合并为最多约每 250 毫秒一次；结果回传和协议 ACK 不等待这个间隔，结束时立即更新最终列表。实际 Tk 计时器可能因系统负载延迟。
- 大量待回传译文只选优先级最高的 8 条，不再每次分配并排序完整候选列表。顺序仍为可见优先、同优先级按原文字典序，单包加入和删除合计最多 8 条。
- 游戏控件的文字及字典版本都未改变时，复用已检查结果，减少重复字典查询；仍读取控件文字来发现动态变化。新译文、校对、删除、控件内容变化和停止恢复继续生效。不对 TextGetter 尚未应用的结果做永久跳过。

## 安装和边界

工作台与配套 Lua 插件一起更新。旧的个人缓存、工程和已导入人工汉化无需清除。运行标记为 `local-reuse-fix-20261023`，默认仍是轻量采集，可选兼容模式；版本标签仍为 0.2.0-rc5，请按提交及 SHA256 区分候选。

离线复用不会拼接猜测未知词，也不会跨渠道/语言对挪用机器缓存。未知名称仍需要用户选定的联网渠道或自己的本机服务。第三方免费服务限流、延迟和语境误译不会因本次调整而消失。

继承上一版轻量扫描的边界：树外自绘界面、TextGetter 反复覆写的文字仍可能漏采。超大 GUI、游戏原生语言包重载和其他模组也可能卡顿。这次没有游戏实测，不承诺零卡顿或完整覆盖。

## 可复现检查

Python：`python -m unittest discover -s tests -v`。

桌面实际 Tk 事件循环：`python tools/check_workbench_ui.py`，需要图形环境；服务被替身或断言拦截，不启动游戏。

排序合成基准：`python tools/benchmark_delta_selection.py --output evidence.json`，比较 20000 条候选选择前 8 条，校验结果相同。时间和临时内存仅反映这一段选择算法，不是整段回传、内存驻留或实机 FPS。

隔离 Lua 检查增加同一控件持续观察 20 次无需重复查询，以及后续文字变化、校对、删除、停止恢复验证。不会执行第三方模组或启动游戏。
