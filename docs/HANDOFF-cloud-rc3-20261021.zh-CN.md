rc2 用户现场第一批 8 条全部失败、无译文，日志把异常统一写成“免费联网翻译暂不可用或超时”。已在本机复现：源码 Python HTTPS 正常，但 PyInstaller EXE 在创建 SSLContext 时立刻抛 FileNotFoundError，尚未发送请求。

原因：本机 Codex 的 Python 3.12.14 运行时修改了 ssl.py，SSLContext 构造会读取 ssl.py 同目录的 codex-rejected-cas.pem；打包遗漏了这个运行资源。不是用户必须配置模型或 API 的问题。

当前源码已修复 build-windows.ps1：从实际构建解释器动态查询该资源，如存在则原样带入包根目录。不硬编码个人路径，不修改该文件内容，不取消证书/主机名验证。普通未修改的 Python 不必有这个文件。

新增 --check-online NEW_JSON：不打开 UI，以固定示例 Open hatch 验证免费联网翻译，写新 JSON 路径；与扫描/安装参数互斥，拒绝覆盖已有输出。运行时缺失文件单独提示 TLS 资源错误，不再伪装超时。

本地 rc3 已构建，验证包中包含该 PEM；实际运行打包 EXE --check-online，退出 0，返回 ok=true、打开舱门、issues=[]，耗时 2.016 秒。此证据是打包后实际 HTTPS 和翻译路径，不是模拟接口，也不是游戏验收。
