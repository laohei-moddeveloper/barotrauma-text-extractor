# rc2：零译文与卡顿修复 · 2026-10-21

此前现场桥接状态显示累计提交约 1400 条、应用译文 0 条。请求/响应编号一致，草稿已允许，但响应 translations 为空。旧版没有逐条错误记录，不能追溯最初触发的网络错误，不能断言是额度耗尽或断网。

## 已修复

- 免费联网翻译逐条处理异常：单条失败不会丢弃同批其他成功结果，也不会阻止后续批次。隔离复现的 4 条中 1 条失败场景，修复前丢失 3 条成功结果，修复后实际桥接文件包含 3 条译文和 1 条错误。
- 失败和格式拒绝明确记录；格式不符的草稿仍供人工校对，但不冒充已应用。最近 200 条诊断写到 `%LOCALAPPDATA%/AbyssText/translation-status.json`，只保存记录 ID、时间与错误，不保存原文。桥接响应附带失败数和最近错误。
- 超时/暂时联网错误冷却 30 秒，同会话每条最多自动尝试 2 次；HTTP 403/429 或服务额度错误冷却 1 小时，无付费回退。不可重试错误保留给人工处理，重启试译会话可重新尝试。
- 修复 MoonSharp/.NET 字符串下失效的 UTF-8 字节范围中文检测。已有汉字及混合中英文本在英文到中文模式保留；其他语言对仍可使用。
- 游戏采集批量由 64 降到 8，预加载每步从 200 降到 32 次访问、缓冲阈值 64。桌面每次调度 4 条、最多 2 个联网请求并发。
- 普通文字回传不再刷新整个语言包。只有语言键 XML 内容变化才重载；控件更新每次最多处理 32 个，分散到多帧。未改变的响应不重复解析 JSON。
- 当前提示框能把已提交的后台文字提升为优先处理，且只提升一次；停止再启动后，即使译文版本相同也可重新应用缓存。
- 桌面结果带会话和语言对范围，旧会话/旧目标语言结果不会写进当前项目。

## 本机交付和恢复

经用户明确要求直接覆盖，两个已有桌面目录中的 EXE 均已更新；自己的 AbyssTextLive Lua 也已更新。没有覆盖游戏 DLL、第三方模组、运行期翻译数据或设置。旧 EXE 和插件脚本已备份；本机部署回执保留在 `.local-release/rc2-local-update-receipt.json`（不提交 Git）。

用户需手动打开更新后的桌面程序并连接已有插件目录。游戏中先停止旧试译，再 F3 执行 `cl_reloadlua`，重新一键试译。覆盖磁盘文件不会自动替换游戏内存里已加载的 Lua。

恢复时先退出桌面程序、停止试译，把回执中对应备份复制回原路径，再重新加载 Lua。GitHub 仅同步任务分支；工坊与公开 Release 暂不发布。
